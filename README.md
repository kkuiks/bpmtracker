# BPMTracker

Windows에서 음원과 악기별 스템을 편집하고, 고정 메트로놈을 추정·검토하여 음악과 클릭을 동기화된 파일로 출력하는 오디오 작업 앱입니다.

현재 버전은 **0.6.6**입니다. 멀티트랙 편집, 재생, 분석, 프로젝트 저장과 파일 출력을 연결한 개발 단계입니다. 분석기는 곡 전체 또는 선택 구간에 대해 일정한 BPM·박자표·마디 첫 박 오프셋을 추정합니다. 자동 템포 변경·변박 분석은 지원하지 않습니다.

## 주요 기능

| 영역 | 기능 |
| --- | --- |
| 음원 가져오기 | WAV·MP3·FLAC, 파일 드롭, 순차 배치, 독립 트랙 또는 연결 스템 가져오기 |
| 오디오 편집 | 이동·복사·분할·트림, 범위 편집, 여백을 보존하는 복사·붙여넣기, 실행 취소·다시 실행, 하단 파형 편집기 |
| 재생·믹싱 | 트랙별 음량·팬·뮤트·솔로, 마스터 음량, 독립 클릭 음량, 구간 반복 |
| 프로젝트 그리드 | Tempo·Signature 트랙, 마디 룰러, Linear·Musical 트랙 시간 기준 |
| 혼합 선택·이동 | 음원·여러 BPM·박자표 동시 선택, 마디·박 단위 묶음 이동, 한 번의 Undo/Redo |
| 분석·검토 | 곡 전체 또는 선택 구간 분석, 예측 클릭 청취, 분석값 수정, 원본 예측 복원, 마디에 맞춘 곡·스템 배치 |
| 정식 표본 검토 | 카탈로그와 승인 맵 확인, 기존 클릭·편집 맵 비교, 별도 표본 수정안 저장 |
| 저장·출력 | `.joljak` 프로젝트, 원본 음원 수집 저장, 같은 시작점·길이의 WAV 믹스·스템·클릭, 템포 맵 JSON·MIDI |

분석 예측과 편집 가능한 프로젝트 맵은 별도로 저장됩니다. **Restore Original Prediction**은 저장된 분석값을 복원하고, **Apply & Align**은 그 값을 프로젝트 맵에 적용하며 곡과 연결 스템을 배치합니다. 일반 오디오 편집은 프로젝트 맵을 이동하지 않습니다.

BPM·박자표는 자동 시작 포인트 없이 전체 값과 선언 포인트를 따로 저장합니다. 해당 종류의 포인트가 없으면 하단바 입력이 프로젝트 전체에 적용되고, 포인트가 있으면 현재 커서에 새 선언을 추가합니다. 박자표는 마디 시작 위치에서 선언하며, 첫 포인트도 이동·삭제할 수 있습니다.

분석값 적용도 포인트가 없는 종류는 프로젝트 전체 값에 반영합니다. 오프셋은 곡·스템을 마디에 정렬하는 데 쓰며, 기존 선언 포인트가 있는 종류만 해당 분석 위치에 새 선언을 추가합니다.

선택한 오디오·템포·박자표를 한 묶음으로 옮길 수 있습니다. 곡의 관련 맵을 자동으로 찾아 묶어 옮기거나 복사하는 명령과 분석 적용 시 충돌 검토는 아직 구현하지 않았습니다. 녹음, VST, MIDI 연주 편집, 타임 스트레칭, 피치 변경, 페이드, FX·버스, 자동화도 현재 범위에 포함되지 않습니다.

## 시작하기

빌드된 Windows 배포 폴더에서는 `Joljak.exe`를 실행합니다. 폴더 전체를 함께 보관해야 하며, 실행 시 별도의 Node.js·Python·WSL 설치나 인터넷 연결이 필요하지 않습니다.

개발 환경에서는 저장소 루트의 **`Start Joljak.cmd`**로 실행합니다. 첫 실행에는 빌드된 UI와 `dist/Joljak-win-x64.zip`이 필요합니다. 이후에는 캐시된 런타임을 재사용하며 현재 앱 파일을 복사합니다. 변경된 빌드를 보려면 앱을 닫고 다시 실행합니다. 소스 저장소에는 배포 런타임과 모델 가중치가 포함되어 있지 않습니다.

1. **Import Audio**로 음원을 가져옵니다. 여러 파일은 **One track**, **Different tracks**, **Aligned stems** 중 배치 방식을 선택합니다.
2. 곡 이벤트를 선택하거나, 이벤트 안에서 분석할 구간을 지정합니다.
3. **Analyze Audio**를 실행합니다. 선택적인 초기 탭은 박 단위 선택에만 사용합니다.
4. 예측 클릭을 청취하고 **Apply & Align**으로 곡과 스템을 프로젝트 마디에 맞춥니다.
5. 오디오와 프로젝트 맵을 편집한 뒤 프로젝트를 저장하거나 WAV·템포 맵을 출력합니다.

**Samples**에서는 정식 표본을 선택해 기존 BPM·박자표·offset·참조 범위를 확인하고 DAW에서 편집할 수 있습니다. 새로 수집한 후보는 **Open candidate review…**에서 준비된 `daw-review.json`을 엽니다. 클릭 기본 볼륨은 이전 기본값보다 +6dB이며, 새 기본값을 0dB로 표시하고 추가 +12dB까지 조절할 수 있습니다. **Save sample draft**는 프로젝트와 수정안을 별도로 저장하며, 승인된 정답 교체는 따로 확정합니다.

자세한 조작과 빌드 방법은 [앱 안내](apps/daw/README.md)에 있습니다.

## 분석 범위

출력은 4분음표 기준 BPM 하나, 박자표 하나, 음원 시작에 대한 마디 첫 박 오프셋 하나입니다. 오프셋은 한 마디 안의 기준 위치로 표현합니다.

- BPM 후보: 30–400 범위의 정수 및 분모 4 이하 기약분수.
- 박자표 후보: 3/4·4/4.
- 입력 구간 전체의 BPM과 박자표가 일정하다고 가정합니다.
- 초기 탭은 음원에서 계산한 후보의 1/2·1·2배 같은 박 단위만 선택합니다. 같은 단위를 고르는 탭은 전체 예측에 동일한 영향을 줍니다.
- 정확한 BPM·박자표·오프셋과 후보 점수는 음원에서 계산합니다. 탭 숫자를 정확한 BPM의 목표나 위상 기준으로 사용하지 않습니다.
- 초기 박자표 입력은 받지 않습니다. 불확실성 표시는 후보 간 점수와 음향 단서의 일치 정도를 나타내며, 정답 확률로 보정되어 있지 않습니다.

프로젝트 맵은 여러 템포·박자표 이벤트를 편집할 수 있지만, 분석기가 자동으로 템포·박자 변경을 찾는 것은 아닙니다. 분석 입력·출력과 명령줄 사용법은 [분석기 안내](experiments/metronome_reconstruction_v1/README.md)에 있습니다.

## 실험 결과

공식 Beat This 1.1.0 final0의 beat·downbeat 관측을 사용했습니다. 추론 입력과 평가 참조를 분리하고, 예측을 저장한 뒤 참조와 비교했습니다.

첫 고정 조건 실험의 평가 집합은 **26개 표본**입니다. 완성 녹음 13개, 원곡 발췌 10개, 합성 녹음 2개, GuitarSet 보조 녹음 1개를 같은 분모로 집계했습니다. 박자표는 4/4 24개와 3/4 2개입니다. 기존 보유 표본 38개 중 나머지 12개는 템포·박자 변화 등 고정 조건 실험의 범위 밖에 있습니다. 아래의 외부 벤치마크와 생성 대조 자료는 별도 집합입니다.

| 조건 · 같은 26개 | 명목 BPM 일치 | 박자표 일치 | 박·마디 최대오차 모두 20ms 이내 | 모두 30ms 이내 |
| --- | ---: | ---: | ---: | ---: |
| 자동 분석 | 19/26 | 26/26 | 18/26 | 19/26 |
| 참조 BPM으로 박 단위를 제공한 진단 | 26/26 | 26/26 | 24/26 | 25/26 |

자동 분석의 BPM 오류는 1/2배 5개와 2배 2개였습니다. 단위 제공 진단은 실제 사람의 탭을 수집한 실험이 아니라, 참조 BPM으로 올바른 박 단위를 제공한 조건입니다. 기준·−5·+5 BPM 힌트는 26개 모두에서 같은 단위를 선택하고 동일한 전체 예측을 냈습니다. 힌트 없는 대조 조건의 BPM 일치는 19/26입니다.

단위 제공 조건의 일반 박 최대오차는 25개가 20ms 이내이며, 가장 큰 값은 San Quentin의 20.52ms입니다. 시작과 끝 사이의 누적 박 위치 차이는 최대 약 0.45ms입니다. **Red Miso는 일반 박 최대오차가 4.92ms지만 마디 첫 박은 약 449.90ms, 거의 한 박 차이**가 남습니다.

명목 BPM 일치는 참조에 기록된 미세한 수치 차이를 포함한 정확한 수치 일치와 구분됩니다. 이 결과는 알려진 개발 표본의 검토된 참조와의 비교이며, 독립적인 제작자 클릭의 밀리초 정확도·실제 탭 성능·미지곡 일반화를 입증하지 않습니다. 시간 오차 기준은 진단용이며, 정식 제품 합격 기준은 정하지 않았습니다.

원음·참조·실행 보고서는 로컬 저장소 내부의 `data/`에 보관하며 Git에는 포함하지 않습니다. 로컬 실행 자료의 구조와 청취 페이지 사용법은 [분석기 안내](experiments/metronome_reconstruction_v1/README.md#recorded-experiments)에 있습니다.

별도의 [자동 평가 도구](experiments/metronome_benchmark_v1/README.md)는 적합성 판정과 참조 생성, 추론, 채점, 보고서 생성을 연결합니다. BabySlakh 20곡 중 고정 조건의 11곡에서 자동 분석과 박 단위 제공 진단 모두 명목 BPM이 9/11개 일치했습니다. 명시된 박자표는 모두 4/4이며 8/8개가 일치했습니다. 2026-10-07 새 실행에서도 모든 예측과 집계가 재현됐습니다. 음원 시간 원점의 독립적인 정합 근거가 없어 정밀 위상 정확도는 채점하지 않았습니다. 기존 26개 집합과 별도인 합성 개발 자료의 MIDI 선언값 비교입니다.

GTZAN의 공개 실음악 특징 999개와 기존 박·마디 주석도 연결했습니다. 사전 규칙에 맞는 472개 중 개발 280개 특징 그룹을 동결 평가하고, 설정을 고정한 뒤 별도 검증 87개를 처음 평가했습니다. 기존 자동 모델의 주석 박 BPM 오차 2% 이내는 각각 252/280개·77/87개였습니다. 개발의 박·마디 첫 박 F1@70ms는 95.22%·87.46%, 검증은 95.50%·85.35%였습니다. 보관 98개 그룹은 추론하지 않았습니다. 원음 디코더·전체 곡 처리·제작자 시계의 정밀 정확도와 모든 원곡·아티스트의 독립성은 이 특징 평가로 확인하지 않았습니다.

같은 고정 BPM·박자표·오프셋을 반환하는 단순 추정기도 비교했습니다. 같은 신경망 관측을 사용하며, 새로운 신경망 학습은 수행하지 않았습니다. 개발·검증 주석 점수는 기존과 비슷했고, 저장된 관측으로 시계 계산만 측정한 10개 입력의 중앙값은 기존 약 3.89초·단순 약 0.033초였습니다. 이 시간에는 신경망 실행·관측 전처리·진단 로그 저장이 포함되지 않습니다.

정확한 시계와 오디오 좌표를 정의한 생성 음악 58개(10개 기본 곡의 변형)에서 박·마디 최대오차 ≤20ms는 자동 조건이 기존 21/57개·단순 26/57개, 참조로 박 단위만 제공한 진단이 기존 30/57개·단순 38/57개였습니다. 단순 방법은 317ms의 시작 지연만으로 박자표가 바뀌는 사례도 있어 기본 추정기는 유지했습니다. 분모 4 이하의 후보로 120.1 BPM을 표현할 수 없는 긴 입력은 사전에 정의한 표현 한계 진단으로 정밀 분모 57개와 구분하며, 전체 58개 집계에는 남았습니다. 해당 입력의 단위 진단은 두 방법 모두 120 BPM을 반환했고 약 214ms의 드리프트가 쌓였습니다. 생성 시계의 좌표 검증은 실제 제작자 시계나 음악적 해석의 유일성을 인증하는 결과와 구분합니다.

개발 280개의 기존 자동 예측에는 주석 BPM 불일치 28개와 박 F1=1·마디 첫 박 F1=0인 17개가 있었습니다. BPM 불일치 28개 중 24개는 비슷한 속도 후보를 이미 계산했으나 선택하지 않은 경우였습니다. 경고가 없는 BPM 불일치도 10개였으므로 경고 표시는 정확도 보증이 아닙니다. 상세 방법·오류·모든 비교 조건과 실패 분모는 [자동 평가 도구](experiments/metronome_benchmark_v1/README.md#recorded-expansion-and-method-comparison)에 있습니다.

별도의 [변속 확장 Step 0 조사](experiments/variable_tempo_step0/README.md)는 실제 변속 자료의 참조 적합성, 기존 템포 후보의 생존, 정답 시계를 제공한 구간 판정과 변경 시점, 고정 자료의 오탐을 조사합니다. 현재 최종 후보군의 누락과 짧은 구간·경계의 불확실성이 남아 자동 조합 단계는 보류했습니다. 앱의 분석기와 기존 고정 실험은 유지했습니다.

## 구현과 검증 상태

Electron과 React/TypeScript로 화면과 프로젝트 편집을 구현했습니다. 재생은 Web Audio의 샘플 시계를 사용하고, 음원 처리·분석·출력은 별도 Python 프로세스에서 실행합니다. 오디오 속도와 원본 파일을 유지하면서 프로젝트 위치와 맵을 편집합니다.

[초기 Windows 통합 감사](apps/daw/audit/README.md)는 편집·재생·추론·저장·복구·내보내기 64개 사례를 기록합니다. 이후의 0.4.2 가져오기·트랙 조사와 0.4.4 오디오 편집 조사는 각 버전의 관찰입니다. **0.6.6은 UI 빌드와 Windows 앱 파일 갱신까지 완료했으며, 0.6.6 앱 자체의 새 실행·재생·저장·회귀 검사나 분석 검증은 수행하지 않았습니다.** 별도 평가 도구의 모델 결과와 앱 실행 검증을 구분합니다.

## 저장소 구성

개발 파일을 찾을 때는 [실험·분석기 안내](experiments/README.md), [관리 도구 안내](tools/README.md), [로컬 데이터 안내](tools/LOCAL_DATA.md)에서 각 영역의 진입점을 확인할 수 있습니다. 기록된 실험과 완료된 일회성 도구는 현재 앱의 분석기와 구분해 두었습니다.

```text
apps/daw/                                Windows 오디오 작업 앱
experiments/metronome_reconstruction_v1/   고정 메트로놈 추정기·평가기·청취 도구
experiments/metronome_benchmark_v1/        표본·참조 적합성 판정·자동 추론·채점
tools/ntm_collection/                     표본 수집·원본 시계 추출·오프셋 검토 도구
data/                                    로컬 샘플·연구 결과·모델 (Git 제외)
```

표본 수집 도구의 입력·출력과 정렬 방식은 [수집 도구 안내](tools/ntm_collection/README.md)에 있습니다. 모든 로컬 샘플은 `data/samples/`에 실제 파일로 모으며, 카탈로그가 등록 여부와 현재 경로를 관리합니다. 연구 결과는 `data/research/`, 모델은 `data/models/`에 보관합니다. 이전 구현은 Git 이력에 남고, 선별한 실패 증거는 현재 연구 자료에 보관합니다. 로컬 자료와 배포 파일은 소스 Git에 포함하지 않습니다.
