## 구현과 검증 상태

Electron과 React/TypeScript로 화면과 프로젝트 편집을 구현했습니다. 재생은 Web Audio의 샘플 시계를 사용하고, 음원 처리·분석·출력은 별도 Python 프로세스에서 실행합니다. 오디오 속도와 원본 파일을 유지하면서 프로젝트 위치와 맵을 편집합니다.

[초기 Windows 통합 감사](audits/README.md)는 편집·재생·추론·저장·복구·내보내기 64개 사례를 기록합니다. 이후의 0.4.2 가져오기·트랙 조사와 0.4.4 오디오 편집 조사는 각 버전의 관찰입니다. **0.6.8은 첫 UI 다듬기의 상단 스크롤바·가져오기 안내·팬 표시·0 기준선과 스냅을 개선하고 UI 빌드·Windows 앱 파일 갱신까지 완료했으며, 0.6.8 앱 자체의 새 실행·재생·저장·회귀 검사나 분석 검증은 수행하지 않았습니다.** 별도 평가 도구의 모델 결과와 앱 실행 검증을 구분합니다.

**0.6.9는 값 입력과 선택·취소 동작의 첫 개선분입니다.** 숫자·dB·위치 입력을 통일하고, 입력 중 값과 적용 위치를 유지하며 텍스트 Undo와 프로젝트 Undo를 구분합니다. 잘못된 입력은 값 옆에 설명을 표시하고, 취소한 팬·음량·범위 조작은 원래 상태로 돌아갑니다. 별도 프로필의 실제 Windows 앱에서 시험용 WAV를 사용한 17개 확인 항목을 통과했습니다. 이번 결과는 해당 UI·조작 범위이며, 분석기 성능이나 전체 저장·출력·장시간 재생의 새 검증 결과는 아닙니다.

**0.6.10은 값 입력과 선택 동작을 개선한 버전입니다.** 하단 BPM을 첫 입력부터 커서 위치의 선언으로 처리하고, 정수 단위 드래그·호버 휠, 고정 자릿수 표시와 위치 구간 폭, 클립 위치·트림의 실시간 반영을 적용했습니다. 복제 트랙을 번갈아 선택할 때 Inspector 컨트롤이 누적되는 문제도 수정했습니다. 별도 Windows 앱의 관련 동작 11개를 확인했고, 복제 트랙은 24회 교차 선택해 컨트롤 개수와 편집 대상을 확인했습니다.

**0.6.11은 타임라인 커서의 시작점과 표시를 수정합니다.** 손잡이를 한쪽으로 잡고 시작점 밖까지 끌었을 때 커서가 몇 픽셀 오른쪽에 남는 문제를 고쳤고, 룰러와 트랙 영역의 커서 선폭·좌표를 통일했습니다. 관련 Windows 확인 7개를 통과했으며, 손잡이 양쪽·Snap 켜짐/꺼짐으로 16회 원점 드래그와 재생 중 동작을 확인했습니다.

**0.6.12는 편집 화면의 배치와 메뉴를 정리한 버전입니다.** 도구막대·Info Line·Inspector·Transport의 배치와 간격을 정리하고, 타임라인 아래로 확대·스크롤을 모았습니다. 클립·범위·트랙·빈 레인·룰러·맵·숫자의 우클릭 메뉴를 하나의 선택·위치·키보드 처리로 연결했습니다. 별도 Windows 앱에서 기본 화면·메뉴 9개 항목을 확인했으며, 범위 및 대상별 편집 확인은 [검사 기록](audits/README.md)에 정리합니다. 이 기록은 해당 버전의 확인 범위를 나타냅니다.


## 0.6.13–0.6.17

0.6.13에서는 별도 Windows 프로필과 프로젝트 자료로 파일 열기·기존 창 전달·복구 우선순위를 확인했습니다. 탐색기 파일 연결을 통한 열기까지 확인한 결과는 아닙니다.

0.6.14의 연속 맵 검사는 렌더러·프로젝트 형식·JSON/MIDI 출력의 기하를 다룹니다. 0.6.15는 원본 샘플레이트와 48kHz 재생 캐시 메타데이터의 불일치를 수정합니다.

0.6.16의 선언 시각 보존은 13개 기하 검사로 확인했습니다. 0.6.17은 중복 가져오기의 버퍼 공유, 작업·Undo 자산의 캐시 유지, 종료 후 재생성 가능한 캐시 정리와 저장·복구 시 재생성을 구현합니다. 구문·TypeScript·프런트엔드 빌드·Windows 파일 조립은 완료됐으며, 최신 캐시·복구·재생의 Windows 실행 검사는 남아 있습니다.
